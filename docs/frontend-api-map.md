# WSK 官网与现有接口

检查依据：`internal/gateway/router/router.go`、`internal/gateway/model/dto.go`。仓库继承了电商后端，尚未完成汽车业务适配。

## 本次替换范围

- `shop/`：旧 React 商城替换为 WSK 官网，包含首页、品牌故事、车型筛选、对比和预约演示。旧代码保留在 Git 历史。
- `frontend/`：保留独立商品管理台，仍与现有后端配套。
- Go 服务、数据库、部署业务逻辑不修改。
- Vite 保留 `/api` 代理至 `http://127.0.0.1:18090`，可通过 `WSK_API_PROXY_TARGET` 改变目标。官网当前不自动请求电商接口。

## 已有接口

| 接口 | 原用途 | 官网适配情况 |
| --- | --- | --- |
| POST /api/v1/auth/register、/auth/login | 注册、登录 | 可复用为未来用户中心，当前官网没有登录入口 |
| GET /api/v1/users/:id | 用户资料 | 未来接入前需要核对公开读取的权限要求 |
| GET /api/v1/products、/products/:id | 商品列表、详情 | 字段只有名称、价格、库存、描述、图片等，不能直接承载完整车型资料 |
| POST /api/v1/products、PUT/DELETE /products/:id | 商品管理 | 保留管理台继续使用 |
| /api/v1/cart、/cart/items | 购物车 | 不适用于品牌展示和试驾预约 |
| /api/v1/orders、/:id/pay、/:id/cancel | 电商订单、模拟支付 | 不等于试驾预约，不复用为预约提交 |
| GET /api/v1/addresses/random | 随机演示收货地址 | 不是门店或预约地点 |
| GET /healthz | 服务健康检查 | 可用于部署验证 |

## 当前数据与后续接口

车型文案在 `shop/models.js` 和 `shop/app.js`；品牌内容在 `shop/about.html`；图片在 `shop/public/assets/`。预约仅在浏览器内演示，不上传、不保存个人信息。

后续需要设计的领域接口（本次尚未实现）：

1. 车型列表与详情：车型代号、类别、配色、图片集、配置资料、发布状态。
2. 试驾预约：车型、联系方式、门店、时间、状态；需后端校验、隐私处理和防重复提交，不能直接转换为电商订单。
3. 门店与可预约时间：提供真实地点和时间，而非随机地址。
4. 品牌内容：可继续保持静态，也可增加版本化内容管理。

本次提交前端基线，不声称已有车型或预约接口，也不把演示成功当作后端保存成功。

上述替换范围记录官网基线。后续部署隔离已将 Docker/K8s 标识、宿主机端口、数据配置及前端代理切换至 WSK 专用默认值，Go 业务逻辑未改动。详见 [部署说明](deployment-isolation.md)。

## 选车购买页面

`shop/purchase.html` 是选车流程的前端演示，复用三款现有概念车型；资料集中于 `shop/vehicle-data.js`，展示页和选购页共用。不复用旧电商订单或支付接口。售价、量产配置和交付能力尚未提供，确认仅在本页显示，不上传数据或创建订单。后续真实购车需单独设计车型配置、报价、库存/交付、购车订单及支付领域接口。
