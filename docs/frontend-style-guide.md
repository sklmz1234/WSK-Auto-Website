# WSK 前端开发样式规范

版本日期：2026-10-19

适用范围：`shop/` 中的 WSK 对外官网。用于新窗口、新会话和后续前端迭代的共同基线。

## 1. 背景与目标

以用户最初提供的 Agentic skill 为基础，将极简控件、明确层级、清晰结果、克制动效与汽车品牌展示结合。视觉应现代、大胆、留白充足，具有汽车品牌的质感与编辑式排版。

本规范依据前面对话中已读取的 Agentic SKILL / DESIGN 内容，以及用户后续明确确认的样式、交互和现有源码整理。原 skill 曾位于桌面 agentic 文件夹，当前该路径已不存在；本文件不是对原 skill 原文的完整复制。

### 基础规则与项目化调整

| 项目 | 原 Agentic 基础 | WSK 当前确认版本 |
| --- | --- | --- |
| 风格 | 现代、大胆、表面层次、极简控件 | 汽车展示、大图、留白、清晰分区 |
| 主色 | 橙色 #FF5701 | 通用行动保留橙色，影片入口增加蓝色 |
| 背景 | 白色、米白 | 米白主体 + 深色页头与设计区 |
| 字体 | Playfair Display、JetBrains Mono | 保留英文排印，中文及表单增加适合的回退字体 |
| 交互 | 对话式、委托式流程 | 根据官网任务使用车型选择、对比和影片，不凭空增加 AI 聊天功能 |
| 输出 | 结构清楚、状态明确 | 页面可浏览、入口可用、演示与真实能力分清 |

### 当前确认版本，优先于历史尝试

- 品牌名：**WSK**；英文全称：**World Super Kinetic**。
- 原始标志：用户提供的银色流线 W。车标形状、圆润回环和向右延伸的细长笔画保持一致。
- **整个页头使用 #181B24 深色，与首页 02 设计区同色。**
- **车标没有独立蓝色、蓝白或其他渐变底板。** 这些方案已被用户替换。
- 页头的车标与导航使用银白或浅色表达。
- “了解我们”位于“探索车型”左边，和其他导航使用统一间距。
- 首页“预览风采”按钮与“自由的想象，始终在线”旁的小圆点为蓝色。
- 视频播放结束后自动恢复原区域的介绍文字与“预览风采”入口。

## 2. 设计令牌与风格基础

### 色彩

| 角色 | 数值 / 现有变量 | 使用方式 |
| --- | --- | --- |
| 通用主强调 | #FF5701 / --primary | 探索车型、预约等主要行动，少量强调线和点 |
| 影片强调 | #2563EB / --accent-blue | “预览风采”、品牌体验区小圆点 |
| 影片悬停 | #1D4ED8 / --accent-blue-hover | 蓝色按钮 hover |
| 主体背景 | #F6F6F1 / --secondary | 官网大面积浅色背景 |
| 白色表面 | #FFFFFF / --surface | 输入框等需要分层的区域 |
| 深色品牌背景 | #181B24 | 页头、首页 02 设计区 |
| 正文 | #111827 / --text | 浅色背景的主要文字 |
| 次级文字 | #626762 / --muted | 浅色背景的辅助说明 |
| 分割线 | #D9DCD6 / --line | 卡片、页脚、内容分隔 |
| 深底正文 | #F6F6F1 | 页头和设计区主要文字 |
| 深底次级文字 | #BCC3CF | 设计区辅助说明 |
| 深底导航高亮 | #FFAB7A | 当前导航与悬停状态 |
| 深底焦点 | #93C5FD | 页头键盘焦点 |
| 成功 / 警告 / 危险 | #16A34A / #D97706 / #DC2626 | 来自原 skill，按实际状态使用，不假定已全部落地 |

优先复用现有 CSS 变量。新增重复色值应提取为语义变量；不要在多个组件中散落近似颜色。色值是默认基线，仍要针对文字大小与背景检查对比度。

### 字体与字号

- 英文标题及展示性排版：Playfair Display。
- 中文展示性标题与叙述：Songti SC、SimSun、serif 回退。
- 标签、序号、英文技术说明：JetBrains Mono、monospace。
- 导航、按钮、表单：Arial、Microsoft YaHei、sans-serif，以清晰易读为先。
- 原 skill 的字号阶梯：14 / 16 / 18 / 24 / 32 / 40px；现有官网英文眉题可用 10–12px，主视觉标题根据版面扩展至 48–64px。
- 小字号只用于辅助标签，不用于关键信息或主要操作。中文正文建议 14–16px，行高约 1.8–2.2。
- 展示标题常用常规字重，避免所有标题都做粗黑。长标题需自然换行，不允许溢出。

### 间距、圆角与分区

- 以 8px 为间距基线：8 / 16 / 24 / 32 / 40 / 48 / 64 / 96px。
- 圆角克制：原 skill 默认 4 / 8px；不要把界面改成大量胶囊、圆球或大圆角卡片。
- 桌面分区常用上下 64–96px，左右约 6%；手机上下 48–64px、左右约 6%。
- 留白服务阅读与层级。对齐、细分割线和背景分区优先于堆叠阴影。
- 网站不是后台管理面板：不要把主展示内容变成密集表格和小卡片墙。

## 3. 组件级规则

### 页头与导航

- 三页共用深色页头，背景与 02 设计区同为 #181B24。
- 原车标可用 CSS 裁切图像外围空白，但不能裁掉标志本体，也不能拉伸。
- 禁止重新添加车标独立渐变底板，禁止反相成黑色标志放在深底。
- 四个导航项必须属于同一个 nav：了解我们 → 探索车型 → 设计与灵感 → 品牌体验。
- 四项使用相同 gap：当前宽屏 32px，较窄桌面 24px；不单独给“了解我们”设置 auto 外边距或额外箭头。
- 桌面页头高度 88px；手机 72px，使用展开菜单，菜单深色保持一致。
- 当前页标记使用 aria-current，并提供足够清楚的高亮、hover 和 focus-visible。

### 按钮、链接与状态

- 主要按钮使用通用橙色；影片入口明确使用蓝色和白字。不要将所有按钮随意统一为蓝色。
- 常规按钮最小高度约 52px，交互目标至少 44×44px。
- 次级操作可用描边按钮或下划线文字链接。箭头只作为辅助图形，不代替明确文案。
- 定义 default、hover、focus-visible、active；按实际行为补充 disabled、loading、error。
- 动画不能是操作完成的唯一提示；错误需提供清楚的恢复或重试方式。

### 首页与车标设计区

- 首屏保留大幅汽车图、简短标题、说明和明确行动入口。
- “探索车型”进入独立车型页；首页缩略车型切换保留。
- 02 区域深蓝背景与原车标图片协调；图像完整缩放，避免左侧回环、右侧长尾被 cover 裁掉。
- 不重新生成或替换用户车标；车型新图也要核对车头标志的一致性。
- 原图如已是独立图片，只修复布局时优先修复 CSS，而不是重新生成整张图。

### 车型页

- 当前概念车型：GT 纯电轿跑、X 家庭 SUV、S 都市掀背。
- 每款使用独立图片、定位、配色和说明，不能只为同一张图换滤镜冒充不同车型。
- 保留分类筛选、当前车型展示、卡片选择、两车对比、预约演示。
- 对比只展示已有的概念设计信息，不能自行编造续航、售价、性能、销量或真实配置。
- 选择状态通过文字和 aria-pressed 等语义表示，不能只靠颜色。
- 若接入真实异步数据，应补齐加载、空结果、错误与重试，不把静态演示说成已接通接口。

### 品牌页

- 独立品牌故事页，保持与首页一致的导航、字体、配色和页脚。
- 现有品牌历史是概念叙事；没有用户提供的事实，不添加虚构成立年份、工厂、奖项或销量。
- 现有配图为设计工作室和山海公路；车头标志需保持 WSK 原始图案。

### 品牌影片

- 按钮文案固定为“预览风采”，在用户点击后才播放。
- 在原区域播放，不自动弹出其他页面，不默认全页自动播放。
- 点击后文字、WSK 装饰和按钮淡出，再显现影片；当前淡出约 420ms，播放器过渡约 500ms。
- 使用用户提供的约 15 秒视频；保持比例、不裁掉车身，不擅自剪辑或更换影片。
- 保留原生 controls、playsinline、按需加载、加载提示和失败恢复。
- 播放结束自动淡出影片，恢复介绍与按钮；手动“返回介绍”或 Esc 也应暂停并恢复。
- 返回后可再次从头播放，焦点恢复到触发按钮；播放时隐藏文字不可继续参与键盘导航。
- prefers-reduced-motion 下取消装饰性过渡。

## 4. 响应式与无障碍

- 默认考虑桌面和手机，当前主要断点为 1100 / 1000 / 680px，按组件需要使用，不为每个元素散加断点。
- 手机分栏堆叠、导航折叠；禁止横向溢出、车图挤压、按钮遮挡、文本截断。
- 目标为 WCAG 2.2 AA。普通文字对比度至少 4.5:1，大字至少 3:1；UI 边界和状态按适用要求检查。不能未经检查宣称整个网站已认证。
- 原生语义 HTML 优先：nav、button、a、form、label、dialog、video。
- 所有主要交互支持键盘；焦点清楚可见，不能出现焦点陷阱。
- 表单必须有标签和必要校验。弹窗支持关闭，关闭后焦点合理恢复。
- 图片提供恰当 alt；装饰图形不重复朗读；加载、错误或成功提示按需要提供 role=status / aria-live。
- 明确支持减少动态效果；改动控件时兼顾强制色彩模式。
- 自动化 DOM 检查不能代替全部无障碍验收；声称屏幕阅读器实测前必须实际执行。

## 5. 内容语气与接口边界

文案简洁、自信、友好、专业、行动明确。用“探索车型”“预览风采”“返回介绍”，不用“点击这里”“提交成功了哦”等模糊或不一致表达。

官网当前使用概念内容，不存在真实车型、门店、试驾预约 API。表单不上传、不保存联系方式。接口情况见 `docs/frontend-api-map.md`。

演示确认文案应明确是本页演示；不能写“工作人员将联系你”或“预约已入库”，除非已经实现并验证对应服务。

## 6. 反模式与维护要求

| 应保持 | 不应引入 |
| --- | --- |
| 语义令牌、统一间距 | 每页各写一套近似配色和间距 |
| 深色统一页头、完整车标 | 白色页头、重新出现的渐变车标底板、标志被裁切 |
| 导航同组同 gap | “了解我们”漂到车标旁或拥有不同间距 |
| 轻量原生页面 | 为普通视觉调整改回旧商城或引入整套新框架 |
| 克制淡入淡出 | 无目的的滚动劫持、连续闪烁和高频装饰动画 |
| 独立车型图片与清晰声明 | 同图换色冒充不同车、伪造真实产品数据 |
| 可维护的组件样式 | 无止境向 CSS 末尾追加相互覆盖的临时规则 |

技术基线为 Vite 多页面、原生 HTML/CSS/JS；官网源码在 `shop/` 根部，媒体在 `shop/public/assets/`。修改源码，构建产物 `shop/dist/` 不提交。

现有样式含历史覆盖规则。后续触及时应在保持当前外观的前提下合并重复规则；不要为整理规范而一次性重写未涉及页面。旧管理台在 `frontend/`，不要误改。

## 7. QA 检查清单

根据变更范围执行，纯文档修改无需重跑构建或视频测试。

- [ ] 品牌名、全称、原始车标一致；所有新增车型图车标正确。
- [ ] 三页深色页头一致，无车标渐变底板，导航顺序和 gap 一致。
- [ ] 橙色通用行动、蓝色影片入口与圆点的角色没有混乱。
- [ ] 字体、间距、小圆角、分区留白与现有风格一致。
- [ ] 首页、品牌页、车型页及全部本地媒体可访问，入口不是空链接。
- [ ] 车型切换、筛选、对比及本次涉及的表单能完成或明确恢复。
- [ ] 视频点击播放、文字淡出、播完自动返回、手动返回与重复播放正常。
- [ ] 桌面与约 390px 手机宽度无横向溢出、遮挡和图片拉伸。
- [ ] 键盘焦点、表单标签、可访问名称、减少动态效果符合本次变更要求。
- [ ] 没有虚构后台保存、产品参数或真实品牌经历。
- [ ] 前端源码变更运行 npm run build，并检查 git diff --check。
- [ ] 没有提交 dist、node_modules、环境密钥或平台凭据。
